# Editorial Style Guide: Generative Systems Psychology

Source issue: https://github.com/LaceyPsych/laceypsych.github.io/issues/103

This guide is the publishing standard for every Generative Systems Psychology
post.

## Core Principle

If narrative and theory conflict, theory wins.

Stories should illuminate Generative Systems Psychology. They should not
simplify, rename, or contradict the framework.

## Framework

Use **Generative Systems Psychology** for the public and editorial name of the
framework. **GSP** is acceptable after the full name has been introduced.

Generative Systems Psychology describes how interacting psychological systems
generate thought, emotion, behavior, coping, identity, meaning, and change over
time.

Use **Psychological Architecture** for the construct inside GSP that refers to
what has been built into the person over time: temperament, development, memory,
attachment, schemas, values, needs, coping patterns, learned expectations,
identity structures, cultural meaning, prior reinforcement, and protective or
risk factors.

Psychological Architecture is not the full framework. It is one foundational
system within the larger generative model.

## Source of Truth

The Generative Systems Psychology LLM Wiki is the canonical reference. The Blog
Knowledge Map determines blog order, primary theory anchor, source material,
public thesis, privacy constraints, and publication status.

If uncertainty exists, defer to the Wiki and knowledge map.

## Article Purpose

Each article should:

- teach one primary concept;
- build curiosity;
- increase psychological precision;
- remain understandable to a general reader;
- preserve accountability;
- reduce flattening labels;
- help readers see how behavior is generated.

Do not try to teach the whole framework in one post.

## Required GSP Moves

Each post should make these moves visible in plain language:

1. Start with an ordinary human scene.
2. Name one primary GSP concept.
3. Locate that concept inside the model.
4. Show the relevant generated-output pathway.
5. Clarify one common misunderstanding.
6. Preserve accountability.
7. End with one reflection, practice, question, or observation.

A useful pathway is:

> event or context -> appraisal -> need or threat activation -> access or
> constraint -> coping or regulation strategy -> generated output -> consequence
> -> feedback -> reinforcement, repair, adaptation, or change

Not every post needs every step. The relevant pathway should still be legible.

## Terms

Use GSP terms consistently when they carry framework meaning:

- Psychological Architecture
- Development
- Body-Brain State
- Appraisal
- Needs
- Goals
- Schemas
- Access
- Context
- Constraint
- Coping
- Regulation
- Dysregulation
- Generated Outputs
- Feedback
- Reinforcement
- Meaning
- Identity
- Self-Actualization
- Change
- Integration

Do not substitute outside terminology when it would change the framework's
meaning.

When introducing established psychology, locate it inside GSP first, then
connect it to the research lineage. Research should deepen the framework, not
displace it.

## Accountability

Understanding is not excusing. Behavior has consequences. Context improves
precision; it does not remove responsibility. Constraint shapes available
options; it does not make every output harmless.

Strong posts hold both:

- how the behavior was generated;
- what responsibility, boundary, repair, or consequence remains.

Avoid determinism. GSP describes influence, interaction, probability, access,
feedback, repair, and change. It does not claim behavior is inevitable.

## Voice

Use a voice that is warm, thoughtful, conversational, intelligent,
psychologically precise, emotionally honest, accessible, and lightly literary.

Avoid academic lectures, motivational speaking, inspirational cliches, excessive
sentimentality, reader-directed diagnosis, overconfident scientific claims, and
language that presents philosophy as validated science.

Humor is welcome when it lowers the barrier to understanding. Use it sparingly.
One memorable image is usually stronger than a stack of jokes.

## Public Safety

Use fictional people, composite examples, generalized situations, public-safe
abstractions, and ordinary nonclinical scenes.

Avoid identifiable client material, confidential details, unnecessary
autobiographical specifics, diagnosing individuals, presenting education as
treatment, or implying that a blog can replace professional support.

Include the site's educational boundary note or an equivalent boundary section.

## Publication Checklist

- [ ] The post is faithful to the GSP LLM Wiki.
- [ ] The post aligns with the Blog Knowledge Map.
- [ ] One primary concept is clearly taught.
- [ ] Supporting dimensions remain secondary.
- [ ] GSP remains the organizing framework.
- [ ] Outside psychological concepts are translated into GSP language.
- [ ] The relevant generated-output pathway is visible.
- [ ] Behavior is presented as generated output, not the whole person.
- [ ] Psychological access is not confused with intelligence or willpower.
- [ ] Accountability remains intact.
- [ ] Understanding is not presented as excusing.
- [ ] The post avoids determinism.
- [ ] Research supports the framework without overtaking it.
- [ ] Philosophical ideas are not overstated as empirical fact.
- [ ] The story serves the theory.
- [ ] Metaphors support rather than replace the model.
- [ ] Humor remains proportionate.
- [ ] Language is accessible to the general public.
- [ ] Privacy and public-safety rules are followed.
- [ ] The ending invites reflection rather than total closure.
- [ ] The post feels connected to the series without mechanically repeating
      prior essays.
