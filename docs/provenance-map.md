## GSP Relationship Notes

For Blog 03, preserve this relationship in future LLM Wiki / knowledge graph
updates:

> Psychological Architecture -> Access -> Generated Output -> Feedback

Expanded pathway:

> something exists within Psychological Architecture -> body-brain state,
> appraisal, context, and constraint influence what becomes accessible ->
> accessible processes contribute to generated output -> output produces
> consequences and feedback -> feedback may affect later appraisal, coping,
> access, reinforcement, repair, learning, and eventually architecture

Nina sequence:

> event -> appraisal -> safety need -> access shift -> body mobilization ->
> coping availability -> generated output -> feedback -> possible repair

This note mirrors the public post while keeping the public-facing claim modest:
access mediates what becomes reachable under threat; it does not make behavior
inevitable or erase accountability.

For Blog 04, preserve this relationship in future LLM Wiki / knowledge graph
updates:

> Context -> Multiple Active Needs -> Need Accessibility and Constraint ->
> Dominant Need -> Generated Output -> Secondary Need -> Second Generated
> Output -> Feedback

Expanded pathway:

> a context activates more than one need at once -> appraisal weighs opportunity
> and demand together -> accessibility determines which needs can be stated and
> which can only be felt -> Constraint Architecture prices each option ->
> whichever need is currently most load-bearing becomes the Dominant Need and
> organizes the visible output -> the Secondary Need is not resolved and keeps
> generating quieter outputs -> feedback from both outputs can be misread as
> inconsistency, ingratitude, or dishonesty

Theo sequence:

> promotion offered -> appraisal as opportunity and demand -> growth need and
> recovery need both activate -> growth need has language, recovery need does
> not -> mortgage and team constrain refusal -> dominant need generates "yes" ->
> secondary need generates delay, flatness, avoidance -> feedback misattributed
> to character -> naming the second need relocates the conflict into a
> conversation

Blog 04 also carries a structural claim worth keeping separate from the
individual pathway: some need conflicts are produced by Constraint Architecture
rather than by the person, and those are negotiations rather than integration
failures.

Public-claim limits for Blog 04:

- Maslow is treated historically and fairly. The pyramid is attributed to
  post-Maslow management writing, not to Maslow, and Maslow's own caveats about
  fixity and multi-motivation are quoted rather than paraphrased.
- The empirical point is narrow: need categories have held up better than the
  ordering claim.
- The Lewin/Miller approach-avoidance gradient is presented as directionally
  useful mid-century work, not as settled mechanism.

## Reference Engine Patterns To Mine Carefully

The simulator includes ten deliberately separated reference engines. Do not
publish these as personality types. Use them privately to generate contrastive
story angles.

- Secure Integrator: flexible regulation and trust.
- Anxious Pleaser: approval-seeking under threat.
- Avoidant Self-Reliant: independence-protective withdrawal.
- Vigilant Controller: safety-driven control seeking.
- Grandiose Striver: status and mastery pressure.
- Depleted Withdrawer: low-energy avoidance after failure cues.
- Principled Idealist: fairness-sensitive value defense.
- Pragmatic Maximizer: analytical, utility-heavy choice style.
- Enmeshed Caretaker: other-directed over-functioning.
- Detached Intellectualizer: abstraction under ambiguity.

## Public Claim Safety

Use these phrases:

- "One way to understand this pattern is..."
- "In therapy-adjacent language, this can look like..."
- "This is not a diagnosis; it is a lens."
- "The useful question is not 'what is wrong with me?' but 'what did this
  situation activate?'"

Avoid these phrases:

- "This means you have..."
- "Your schema is..."
- "People like this always..."
- "The simulator predicts..."
- "Science proves..."
